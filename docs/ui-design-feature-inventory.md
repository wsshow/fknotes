# FKNotes 当前功能与 UI 设计规格

> 文档用途：作为 UI 设计师或 UI 设计智能体产出 FKNotes 全量界面设计稿的产品输入。
> 审计基线：2026-07-23，当前 `main` 分支。
> 适用范围：当前代码中用户可到达、可操作的正式功能；调试专用能力和暂未开放的技术底座会单独标注。
> 产品名称：中文使用“非空笔记”，英文使用“FKNotes”。

---

## 1. 如何使用这份文档

这不是未来愿望清单，而是当前产品界面的事实清单。设计时请按以下标记理解功能边界：

- **正式功能**：当前用户能够从正式界面进入，必须提供完整设计。
- **条件功能**：只有在安装模型、授予权限、满足模型能力或进入特定状态后出现，必须设计入口和条件状态。
- **Debug 专用**：仅调试构建可见，不应进入面向普通用户的正式信息架构。
- **暂未开放**：代码中存在服务、数据结构或孤立页面，但当前没有正式用户入口；不能当作已上线功能放进主流程。

若本文件与旧版 README、历史设计文档或截图不一致，以本文件描述的当前实现为准。

### 1.1 设计稿的首要目标

1. 让笔记的创建、查找、编辑与分享成为最短路径。
2. 保持“简约现代、清爽干净，但不单薄”的视觉感受。
3. 把本地 AI、模型下载、权限和错误状态表达清楚，不制造虚假的可用感。
4. 让所有破坏性操作、数据迁移和 AI 写入都保持可控、可确认。
5. 不重新引入已经被产品决策移除的冗余导航和低价值分类。

## 2. 产品定位与不可改变的产品原则

### 2.1 产品定位

FKNotes 是一款本地优先、隐私优先的多媒体富文本笔记应用。核心数据默认保存在设备本地；AI、朗读和语音识别依赖用户主动安装的端侧模型；不要求账号登录。

### 2.2 当前核心原则

- **主页就是完整笔记库**：不再拆分“资料库”和“数据”为两个一级页面。
- **单一主入口**：没有底部导航栏，主页承担搜索、浏览和新建笔记。
- **本地优先**：笔记、正文内附件、聊天记录和模型均有各自的本地存储边界。
- **AI 可控**：AI 对笔记的写入必须发生在明确的编辑上下文中；聊天工具写操作必须先预览、再确认。
- **永久删除透明**：当前没有回收站，删除是永久删除，必须确认。
- **无历史兼容负担**：当前笔记以新的 SQLite + Quill Delta 数据模型为准，不为旧 Markdown 数据库设计迁移界面。
- **移动端优先**：当前重点验证 Android；iOS arm64 的部分本地模型能力具备技术支持。相机、录音、本地推理等能力不应假设桌面端或 Web 已完整可用。

### 2.3 明确不存在的一级功能

设计稿中不要添加以下内容：

- 底部导航栏。
- 独立的“资料库”一级页。
- 独立的“数据”一级 Tab。
- 收藏、归档、回收站分类。
- 账号、登录、会员、云端 AI 或在线笔记空间。
- 自动云同步、后台云同步。
- 深色模式切换。
- 首页自动聚焦搜索框。
- 编辑器顶部固定的图片删除按钮。

## 4. 全局视觉与交互基线

### 4.1 当前视觉方向

- Material 3，当前仅浅色主题。
- 大面积低对比浅灰背景，白色内容面，蓝灰色为主要强调色。
- 不使用高饱和红、橙作为常规按钮或大面积面板颜色。
- 卡片以留白、细边框和非常轻的阴影建立层级，不使用厚重投影。
- 圆角克制而统一；浮动按钮和输入面板可以更柔和，但不能形成“果冻感”。
- 图标使用简洁线性或圆角线性风格；只有明确选中或状态反馈时使用实心图标。
- AI 和图片入口在编辑器工具栏中不单独添加高饱和背景。
- 动效应短促、低存在感，用于状态切换、底部面板、列表插入和内容生成，不做装饰性长动画。

### 4.2 当前颜色语义

| 语义 | 当前参考值 | 使用范围 |
| --- | --- | --- |
| 主文字 Ink | `#20272F` | 标题、正文、主要图标 |
| 次文字 Muted | `#69737E` | 说明、时间、次级信息 |
| 弱文字 Subtle | `#9AA2AA` | 占位、不可用提示 |
| 页面背景 Canvas | `#F6F7F8` | 主页面背景 |
| 内容面 Surface | `#FFFFFF` | 卡片、面板、输入区 |
| 次内容面 | `#F0F2F4` | 图标底、弱选中、占位 |
| 分割线 | `#E3E6E9` | 细边框、列表分隔 |
| 主强调色 | `#627486` | 主按钮、选中、链接 |
| 主强调按压色 | `#4C5E70` | 按压态 |
| 主强调浅底 | `#EDF2F5` | 轻选中、标签 |
| 成功 | 低饱和绿灰 | 成功状态 |
| 警告 | 低饱和棕灰 | 警告状态 |
| 危险 | 低饱和红 `#A45D59` | 永久删除、失败 |

设计智能体可以优化具体色值，但必须保留“浅色、低饱和、现代、中性”的整体关系。

### 4.3 尺寸与组件节奏

- 基础间距：4、8、12、16、20、24、32。
- 主要圆角：12、16、20、26；药丸型只用于标签、筛选和紧凑状态。
- 常用图标按钮命中区域不小于 44 × 44。
- 页面左右主边距通常为 20。
- 输入框、卡片、底部面板要有清晰但不过量的呼吸空间。
- 空状态与新建按钮位于页面中上部和安全区上方，不能沉到视觉底部。

### 4.4 全局文本和多语言

- 中文首选系统字体链：PingFang SC / Noto Sans CJK SC / sans-serif。
- 品牌标题或部分分享主题可以使用克制的衬线体。
- 正式支持：
  - 跟随系统。
  - 简体中文。
  - English。
- 设计必须允许英文文案比中文更长，避免固定宽度文字按钮。
- 数字、文件大小、日期、时间和模型速度要考虑本地化。

### 4.5 全局反馈模式

- 成功、普通提示、错误使用轻量浮层提示。
- 页面级加载使用居中进度或骨架状态。
- 破坏性操作使用确认对话框。
- 需要连续操作或包含多个选项时使用底部抽屉。
- 文本选择菜单为品牌化轻量浮层，仅保留剪切、复制、粘贴、全选和系统支持的分享。
- 所有加载、失败、禁用、权限缺失和空状态都必须有可理解的文字，不只依赖图标。

## 6. S-01 启动与初始化

### 6.1 正常启动

- 必需初始化在 Flutter 首帧前完成。
- 正常情况下保留原生启动页，不再叠加第二个 Flutter 加载页。
- 初始化内容包括本地文件目录、未完成恢复事务处理、模型下载源策略和语言设置。

### 6.2 初始化失败

初始化失败时显示品牌失败页：

- 品牌标识。
- “非空笔记 / FKNotes”字标与品牌短语。
- 页面底部显示本地存储初始化失败信息。
- 不进入主页，不展示不可用的导航。

设计要求：错误状态仍应保持品牌一致性，但错误信息必须足够明确，不能只展示装饰性 Logo。

## 7. S-02 应用锁与隐私遮罩

这是全局覆盖层，会阻止底层页面交互并排除底层可访问性语义。

### 7.1 状态

1. **读取安全设置**：加载指示、正在准备应用锁。
2. **等待系统认证**：等待指纹、人脸或设备密码。
3. **已锁定**：锁图标、说明、认证并解锁按钮。
4. **认证失败**：展示可本地化的失败原因并允许重试。
5. **认证被取消 / 不可用 / 锁定 / 暂时不可用**：分别给出明确反馈。
6. **隐私遮罩**：应用切后台或系统截图切换期间隐藏内容，只显示“内容已隐藏”，不一定要求再次解锁。

### 7.2 视觉组成

- 左上品牌头。
- 居中的认证卡片。
- 底部系统认证与隐私说明。
- 使用设备现有认证能力，不设计应用自有 PIN 键盘。

## 8. H-01 主页 / 完整笔记库

### 8.1 页面职责

主页同时承担：

- 笔记总览。
- 全局搜索。
- 打开笔记。
- 新建笔记。
- 笔记快捷操作。
- 批量操作。
- 进入本地助手。
- 进入本地数据与设置。

### 8.2 顶部区域

- 主标题“非空笔记”。
- 当前笔记数量。
- 本地助手入口：闪光 / AI 语义图标。
- 本地数据与设置入口：调节 / 设置语义图标。
- 搜索框。

重要行为：

- 从子页面返回主页时，搜索框不得自动聚焦。
- 键盘不得因为返回主页自动弹出。
- 搜索输入采用约 280 ms 防抖。
- 搜索范围包括标题、可见富文本、标签、附件名，以及已存在的 OCR / 转写元数据。
- 列表预览不能出现 Markdown 标记或附件文件名。
- 列表顺序固定为“置顶优先，其余按更新时间倒序”；当前没有排序、筛选或视图切换控件。

### 8.3 笔记卡片

每张卡片可包含：

- 标题；空标题显示“无标题”。
- 富文本语义预览：显示渲染后的文字效果，不显示 `**`、`##` 等原始语法。
- 更新时间。
- 标签 Chip。
- 置顶状态。
- 图片笔记可在右侧显示一张缩略图，缩略图需在卡片内垂直居中。
- 更多菜单。

更多菜单：

- 置顶 / 取消置顶。
- 永久删除。

图片相关规则：

- 内容摘要不展示图片文件名或附件占位文字。
- 缩略图读取失败时显示中性占位。
- 右侧缩略图不能把正文区域压缩成难以阅读的窄列。

### 8.4 批量选择

长按任意笔记卡片进入批量选择模式。

批量模式包含：

- 当前选中数量。
- 退出选择。
- 全选。
- 批量置顶 / 取消置顶。
- 批量永久删除。
- 点击卡片切换选中状态。
- 操作执行期间禁用重复点击并显示忙碌状态。

批量删除必须二次确认，并明确“永久删除、无法从回收站恢复”。

### 8.5 新建笔记

- 主页右下角唯一的悬浮新建按钮。
- 按钮位于系统安全区上方，并额外上移，不能紧贴屏幕底部。
- 空状态时仍保留同一个入口，不额外放置重复的新建按钮。
- 资料库内部不存在第二个新建入口。

### 8.6 页面状态

- 首次加载。
- 有数据列表。
- 空库：空状态位于内容区域中上部。
- 搜索无结果。
- 搜索中。
- 加载失败，可重试。
- 单条笔记正在执行操作。
- 批量操作进行中。

## 9. E-01 富文本笔记编辑器

### 9.1 数据与编辑模型

- 单篇笔记只有一个连续的 Flutter Quill 编辑上下文。
- 正文的权威格式是 Delta，不是 Markdown 文本。
- 原生选择、全选、选择手柄、撤销、重做和回车换行覆盖整篇正文。
- 标题独立于正文，但同一页面自动保存。
- 自动保存默认采用约 700 ms 防抖，并在返回、应用生命周期切换前冲刷待保存内容。
- 图片、录音、分割线和表格是正文内的块级 Embed。

### 9.2 顶部栏

从左到右：

- 返回。
- 自动保存状态。
- 本地朗读 / 停止朗读。
- 更多菜单。

自动保存状态：

- 自动保存已启用。
- 有待保存修改。
- 正在保存。
- 已保存到本机。
- 保存失败；点击状态可重试。

更多菜单：

- 以图片分享笔记。
- 编辑标签。
- 置顶 / 取消置顶。
- 立即保存。
- 放弃未保存的新笔记，或永久删除已保存笔记。

删除或离开时的特殊状态：

- 未保存的新空白笔记不落库。
- 有未保存更改且保存失败时，离开需提供重试、放弃等明确选择。
- 删除已保存笔记必须确认。

### 9.3 标题与标签

- 大号标题输入框。
- 无标题时使用轻量占位文案。
- 标签在标题下方显示。
- “添加标签”入口。
- 标签可以直接移除。
- 标签编辑最多保留 8 个，支持中文逗号和英文逗号分隔，忽略大小写重复。

### 9.4 正文

支持：

- 普通段落。
- 标题层级。
- 加粗。
- 斜体。
- 下划线。
- 删除线（可由 Markdown 粘贴产生）。
- 行内代码。
- 链接。
- 待办列表。
- 无序列表。
- 有序列表。
- 引用。
- 代码块。
- 分割线。
- Markdown 表格。
- 图片块。
- 录音 / 音频块。

正文行为：

- 回车正常换行。
- 全选选中整篇正文，不限制在局部块。
- 长按选择手柄可以跨整篇正文移动。
- 点击图片或音频卡片不会把文本光标放在卡片前后。
- 图片和音频各自独占一行。
- 长按图片或音频卡片可以拖动调整位置。
- 拖动时显示抬起反馈、插入位置提示，并支持靠近边缘自动滚动。
- 完成一次块移动只形成一个撤销步骤。

### 9.5 系统剪贴板与 Markdown 粘贴

普通文本保持原生粘贴体验。检测到具有语义的 Markdown 时，自动转换为原生富文本：

- 1–6 级标题。
- 加粗、斜体、删除线。
- 行内代码。
- 链接。
- 换行。
- 无序、有序和任务列表。
- 嵌套列表。
- 引用。
- 代码块。
- 分割线。
- GitHub Flavored Markdown 表格。

规则：

- 用户粘贴后看到的是渲染结果，不是原始 Markdown 标记。

- 块级 Markdown 在合理的行边界插入。
- Android 输入法直接粘贴也要走同一转换路径。
- HTML 实体需要正确还原，不能显示 `&quot;`。
- Markdown 图片语法只保留安全的替代文字，不偷偷加载远程图片。
- 系统剪贴板中的实际图片可以导入为受管理的本地图片块。

## 11. E-03 图片插入与图片操作

### 11.1 插入图片

编辑器图片按钮打开来源抽屉：

- 从相册选择。
- 使用相机拍摄。

需设计：

- 正常选取。
- 相机 / 系统照片选择器自身的权限或取消结果。
- 导入中。
- 导入失败。
- 图片文件损坏或无法读取。

当前图片入口没有应用自绘的权限解释页；无法选取或导入时统一反馈失败。不要为当前版本额外虚构一个图片权限设置流程。

### 11.2 图片块

- 占正文整行，按实际比例显示。
- 不设置固定宽高、最大显示高度或裁切窗口。
- 图片块占满正文栏，图像高度由原始宽高比自然计算；大图等比缩小，不另设固定像素宽高。
- 外层使用冷白纸面相框、细描边、轻纸影和机械蓝短线节点；设计感来自框架而非改变图片比例。
- 不在右上角永久悬浮删除按钮。
- 图片未被点击时不显示工具栏。
- 滚动经过图片不能误触发工具栏。
- 单击图片后显示图片操作栏。
- 单击图片本身不出现文本光标。

图片操作栏：

- 查看原图。
- 复制到系统剪贴板。
- 编辑。
- 详情。
- 删除。

“编辑”二级抽屉：

- 重命名显示标题。
- 从相册替换。
- 使用相机替换。

“详情”抽屉：

- 图片预览。
- 原始文件名。
- MIME 类型。
- 文件大小。
- 创建时间。
- 更新时间。

替换图片时保留当前图片块身份和用户定义的显示标题；失败时回滚原图。

- 点击表格后显示块操作栏和删除表格。

## 14. E-05 编辑器内 AI 输入面板

### 14.1 入口与定位

- 点击编辑器工具栏第一个 AI 图标唤起。
- 复用本地助手的轻量输入语言，但保持编辑器场景自己的紧凑样式。
- 面板从底部工具栏上方展开，并自动聚焦自己的输入框。
- 再次点击或关闭按钮可收起。

### 14.2 输入能力

- 自由输入需求，最多 2000 字符。
- 1–4 行自适应输入。
- 快捷建议：
  - 继续写作。
  - 整理成列表。
  - 扩展想法。
- 提交按钮。

### 14.3 写入语义

- 有文本选区：AI 以选区为上下文，并流式替换该选区。
- 无选区：AI 读取整篇笔记作为上下文，在当前光标位置流式插入。
- AI 输出中的 Markdown 被转换为原生富文本。
- 生成期间若文档在预期范围外发生变化，停止写入并提示重新尝试，避免覆盖用户的新编辑。

### 14.4 状态

- 空闲输入。
- 正在检查模型。
- 模型缺失。
- 正在加载模型。
- 正在生成。
- 用户停止。
- 生成完成。
- 无输出。
- 生成中断或失败。
- 文档已经变化，不能继续写入。

生成后操作：

- 撤销本次 AI 插入，恢复原文和原选区。
- 继续提出新需求。
- 失败后重试。
- 生成中停止并保留已有部分内容。

### 14.5 模型缺失

- 先显示“需要本地语言模型”对话框。
- 提供“稍后再说”和“管理模型”。
- 模型未下载时，底部 AI 面板必须保持空闲 / 等待选择，不得同时伪装成“正在加载模型”。

1. 一封非空来信。

- 4:5 竖版。
- 3:4 笔记卡片。
- 9:16 故事。
- 16:9 横版。
- A4。
- 长图。
- 自定义。

方向：

- 竖向。
- 横向。
- 长图不开放横向切换。

自定义限制：

- 最短边不小于 480 px。
- 最大宽度 4096 px。
- 最大高度 12000 px。
- 总像素不超过 2000 万。

### 16.4 清晰度与密度

清晰度：

- 标准：短边 1080 px。
- 高清：短边 1440 px。
- 超清：短边 2160 px。

- 舒展。
- 标准。
- 紧凑。

- 是否包含标题。
- 是否包含日期。
- 是否包含标签。
- 是否包含图片。
- 是否包含附件。

无对应内容时相关开关禁用。

来源标记：

- “来自「非空笔记」”始终包含。
- 以锁定状态展示，用户不可关闭。
- 来源标记不能漂浮在正文中，也不能挤压最后一行内容。

### 16.6 分享内容的渲染

分享图必须保留笔记的语义样式：

- 段落和行内富文本。
- 标题。
- 无序 / 有序 / 待办列表。
- 引用。
- 代码块。
- 分割线。
- 表格。
- 图片和附件。

分页规则：

- 固定比例自动分页，不能截断最后一行。
- 最后一页根据实际内容收紧，不留下无意义的大块空白。
- 保留合理的底部安全留白和来源区呼吸空间。
- 表格按行分页，跨页时重复表头。
- 长图将全部内容生成一张完整 PNG，底部内容不能被截断。

### 16.7 输出

- 生成一张或多张有序 PNG。
- 使用系统分享面板。
- 导出期间显示页数进度。
- 失败时给出可重试的错误反馈。
- 用户的样式、画幅、密度和内容选项在本地记忆。

## 36. 跨页面能力与共同状态

### 36.1 本地推理资源状态

编辑器 AI、聊天、实时听写、音频转写和朗读共享本地重计算资源。设计需要统一表达：

- 待机。
- 正在准备后端。
- 正在加载模型。
- 正在生成 / 识别 / 合成。
- 停止中。
- GPU 或专用后端失败后回退 CPU。
- 资源被其他任务占用。
- 模型文件缺失。
- 平台不支持。
- 内存不足或模型不适合当前设备。
- 释放模型。

不要在“模型未下载”时提前显示“正在加载模型”。

### 36.2 权限

需要统一设计的权限场景：

- 相机。
- 相册 / 系统照片选择器。
- 麦克风。
- 系统生物识别或设备凭据。
- 外部文件读取 / 保存通过系统选择器完成。

权限反馈按系统和当前实现区分：

- 相机、相册和文件由系统选择器主导；用户取消时安静返回，导入失败时显示错误。
- 麦克风由应用明确解释权限用途；拒绝后可前往系统设置。
- 应用锁由系统认证界面处理取消、不可用、锁定和凭据缺失。
- 平台或功能不支持时显示明确说明。

### 36.3 错误与恢复

- 所有错误要提供用户能执行的下一步。
- 网络错误不得与本地模型错误混淆。
- 保存失败不能静默丢数据。
- 恢复、同步、模型安装等不可中断事务需要阻止误返回。
- 已经生成的 AI 部分输出在用户停止后可以保留。
- 附件替换失败要恢复旧文件。
- 备份恢复失败要回滚当前数据。

### 36.4 可访问性

- 图标按钮都有 Tooltip / 语义标签。
- 颜色不是唯一状态信号。
- 选择、录音、生成、同步等动态状态使用可被辅助技术感知的实时文案。
- 文本允许系统缩放；关键信息不能依赖固定高度。
- 触控命中区域至少 44 × 44。
- 弹窗和抽屉有明确焦点顺序。

### 36.5 外部内容与链接安全

- AI Markdown 回答中的远程图片不直接联网加载，统一显示“远程图片已阻止”的中性占位，避免打开私人内容时发生外部请求。
- Markdown 链接只允许 `http`、`https` 和 `mailto`。
- 打开链接前显示目标域名和隐私确认，再交给系统外部应用。
- 无效协议、没有可处理应用或打开失败时分别反馈。

## 39. 关键用户流程

### 39.1 新建并编辑笔记

```text
主页新建

→ 返回主页
```

```text
复制 Markdown
→ 在正文粘贴
→ 识别语义
→ 转换为 Delta 富文本
→ 标题、列表、表格、分割线等直接渲染
→ 作为一次可撤销编辑
```

### 39.3 编辑器内 AI 写作

```text
定位光标或选择文字
→ 点击 AI
→ 输入需求 / 选择快捷建议
→ 检查本地模型
→ 流式写入当前位置或替换选区
→ 停止 / 撤销 / 继续
→ 自动保存
```

### 39.4 分享长图

```text
编辑器更多菜单
→ 制作分享图
→ 选择样式
→ 选择长图
→ 配置内容和密度
→ 预览完整内容
→ 生成单张 PNG
→ 系统分享
```

### 39.5 本地助手引用笔记

```text
主页进入本地助手
→ 添加笔记上下文
→ 搜索并多选笔记
→ 输入问题
→ 本地模型生成并展示来源
→ 点击来源打开原笔记
```

### 39.6 从当前笔记写回 AI 回答

```text
从笔记上下文进入聊天
→ 获得助手回答
→ 写回笔记
→ 选择替换 / 插入下方 / 追加

→ 确认
```

### 39.7 首次使用本地模型

```text
本地数据
→ 从备份恢复
→ 选择外部文件或历史备份
→ 查看范围和替换警告
```

## 41. 设计交付建议

建议 UI 设计智能体按以下顺序产出，确保信息架构和组件先稳定：

1. 全局设计 Token：颜色、字体、间距、圆角、阴影、图标、状态色。
2. 通用组件：顶部栏、卡片、列表行、搜索框、标签、按钮、弹窗、底部抽屉、空状态、错误状态、加载状态。
3. 主页与批量选择。
4. 编辑器与键盘 / 工具栏 / 媒体块 / AI 面板。
5. 分享图配置页和 15 种分享模板。
6. 本地助手、引用、角色、会话和写回确认。
7. 本地数据、备份、恢复、同步、安全设置。
8. 本地模型全套状态。
9. 启动、应用锁和跨页面异常状态。
10. 手机竖屏主稿，以及分享页等关键页面的宽屏适配稿。

每个页面交付时应同时标注：

- 页面 ID。
- 入口和返回路径。
- 默认状态。
- 空、加载、失败和禁用状态。
- 键盘与系统安全区行为。
- 主要组件的滚动边界。
- 破坏性操作的确认层级。
- 哪些按钮受模型、权限或平台能力限制。

## 42. 设计验收红线

出现下列任一情况，应视为与当前产品不一致：

- 重新加入底部导航或收藏 / 归档 / 回收站。
- 首页进入后自动弹出键盘。
- 将 Markdown 原始标记当作正文或卡片预览。
- 图片、音频卡片点击后出现文本光标。
- 图片右上角永久显示删除按钮。
- AI 或图片图标使用与整体体系割裂的高饱和底色。
- 分割线或表格右侧永久显示孤立删除图标。
- 固定比例分享图留下大块无意义空白，或长图截断底部。
- 分享图右上角放应用 Logo。
- 允许关闭“来自「非空笔记」”来源标记。
- 模型未下载时同时显示“正在加载模型”。
- AI 写操作不经过用户确认就修改其他笔记。
- 把备份描述为包含聊天、模型或全部设备设置。
- 把手动云同步设计成自动 / 后台同步。
- 用深红、深橙作为大面积常规页面主题色。
- 把暂未开放的 OCR、音频转写、视频 / 文件插入画进当前正式主流程。

这份规格的目标不是限制视觉创意，而是让视觉创新发生在正确的信息架构、真实功能和可靠状态之上。
