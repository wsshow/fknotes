# 编辑器统一文档架构重构

## 背景与问题

旧编辑器为每个语义块创建一个独立 `TextField`。这种结构便于绘制标题、列表和附件，但每个输入框都拥有独立的光标、选区、输入法连接和撤销上下文，因此系统的“全选”和选择手柄天然只能停留在单个块内，多光标和输入法状态竞争也需要额外补丁处理。

本次重构不再用跨输入框坐标换算模拟整篇选择。目标是让一篇笔记只拥有一个文本输入与选择上下文，同时继续保留现有块数据、Markdown 导入导出和富文本 JSON，做到无数据迁移升级。

## 目标架构

编辑器分为四层：

1. `NoteDocument`：结构化文档，保存块类型、块属性、内联样式和嵌入节点，是编辑期间的事实来源。
2. `NoteDocumentEditingController`：维护整篇文档的线性字符空间，将全局文本偏移映射到块和块内偏移，只对系统暴露一个 `TextEditingValue`。
3. 统一编辑表面：整篇笔记只有一个 `EditableText/TextField`、一个 `FocusNode`、一个输入法连接和一个系统选区。
4. 持久化适配器：继续使用 `NoteBlockCodec` 输出 Markdown，使用 `NoteRichDocumentCodec` 无损保存本地样式和块元数据。

核心约束：

- 光标和选区始终使用整篇文档的全局偏移，块组件不得自行持有光标。
- Markdown 只存在于导入导出边界，编辑区不直接显示 Markdown 标记。
- 块分隔符属于控制器内部协议，复制、分享和持久化时必须转换为真实段落边界。
- 文档修改必须通过统一事务进入历史记录，不能同时触发系统历史与块历史。
- 标题、列表、待办、引用、代码块和嵌入节点只改变呈现与结构，不创建新的文本输入连接。

## 分批迁移

### 第一批：普通段落统一输入

- 纯段落笔记切换为单一编辑表面。
- 支持整篇全选、跨段拖动、复制粘贴、内联格式、撤销重做、语音听写和大文档节流。
- Enter 创建段落，Backspace 在段落边界合并段落。
- 遇到尚未迁移的结构化块操作时，无损降级到旧块渲染器。

### 第二批：文本型结构块

- 将标题、引用、代码块和行级样式加入统一控制器。
- 使用块范围样式构建统一 `TextSpan`，保持不同字号、字体、背景和引用装饰。
- 删除上述块类型的旧编辑器降级路径。

### 第三批：列表与待办

- 迁移无序列表、有序列表、待办、缩进、连续编号和勾选操作。
- 前缀由块呈现层生成，字符映射层明确区分内容偏移与装饰偏移。
- Enter、Backspace 和 Tab/Shift+Tab 通过文档事务改变块结构。

### 第四批：嵌入节点

- 迁移分割线、附件和 Markdown 表格。
- 嵌入节点在全局字符空间中占用稳定占位符，选择手柄可以跨越，但不能把内部按钮当作文本。
- 表格编辑使用独立弹层事务，确认后一次性回写文档节点。

### 第五批：收口与删除旧核心

- 统一 Markdown 粘贴、AI 局部替换、听写、撤销重做和草稿恢复路径。
- 增加超长笔记、中文输入法、选择手柄、横竖屏和低端设备性能回归。
- 删除多个块级 `TextField`、降级开关和旧焦点协调代码。

## 验收标准

每一批都必须满足：

- `flutter analyze` 无问题。
- 编辑器定向测试全部通过，并补充本批新增交互测试。
- 全量测试通过。
- 旧 Markdown 和富文本 JSON 能无损打开、编辑、保存并再次打开。
- 任意时刻最多只有一个可见光标和一个输入法连接。
- 批次完成后形成独立提交，可单独回滚且不依赖未提交代码。

性能目标：普通输入只更新受影响的字符属性和块映射；大文档持久化继续使用 120ms 合并写入；选择操作交给 Flutter 的单一原生选区处理，不在拖动帧内遍历并换算所有块坐标。
